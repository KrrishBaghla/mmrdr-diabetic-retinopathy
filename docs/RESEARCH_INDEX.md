# Paper 2 — New Research Programme Index

Three novel research directions to push the MMRDR diabetic-retinopathy model past its current mature
baseline, all attacking the same core problem from different angles: **the rarest lesions (NV, VH, RD —
the ones that define sight-threatening Proliferative DR) are exactly the ones standard training ignores.**

This file is the map. Each direction lives in its own **self-contained** folder with full documentation
(`README.md`, `PLAN.md`, `RESEARCH_NOTES.md`, `IMPLEMENTATION_GUIDE.md`, `STATUS.md`) and one Kaggle-ready
notebook generated by a `create_nb.py` (repo convention, matching `clinical_safety_pdr_2/create_nb.py`).

**Nothing in the prior experiment folders was modified.** The three prior experiments
(`clinically_weighted_loss_1/`, `clinical_safety_pdr_2/`, `contrastive_learning_lesions_3/`) are treated as
completed reference research. All three new directions **reuse folder 3's mature pipeline** — `UWF_SupConDRNet`
(ResNet-50 + FPN + SupCon heads), `AsymmetricFocalLoss`, `SupConLoss`, `apply_uwf_mask`, `calculate_metrics`,
the `save_checkpoint`/`load_checkpoint` + AMP + `nn.DataParallel` Kaggle template — so every measured gain is
attributable to the one thing each direction changes.

## The shared baseline to beat
Folder 3 (`contrastive_learning_lesions_3/`), UWF modality, fully trained (the only real numbers we have):

| Metric | Val |
|---|---|
| Grade Accuracy | 76.3% |
| Grade Quadratic Kappa | 0.922 |
| Lesion macro-F1 | 0.738 |
| Lesion macro-AUC | 0.951 |

The headline clinical-safety metric all three directions optimize is **per-rare-class recall (NV/VH/RD)** —
not overall accuracy or macro-AUC, which hide rare-class failure under extreme imbalance.

## The three directions (the three levers)

| # | Folder | Lever it pulls | Notebook | Compute | Risk | Novelty |
|---|--------|----------------|----------|---------|------|---------|
| 1 | [`research_dynamic_resampling/`](research_dynamic_resampling/README.md) | *What samples the model sees* — recall-driven curriculum resampling (RDCR) | `Dynamic_Resampling_UWF.ipynb` | Low–Med | Med | Med |
| 2 | [`research_uncertainty_loss/`](research_uncertainty_loss/README.md) | *How task losses are balanced* — learned Kendall-2018 uncertainty weights replacing the guessed `1:1:0.5:0.5` | `Uncertainty_Weighted_MTL_UWF.ipynb` | Low | Low | Low–Med |
| 3 | [`research_synthetic_generation/`](research_synthetic_generation/README.md) | *How much rare data exists* — conditional generation (latent-diffusion+LoRA primary / StyleGAN2-ADA fallback) | `synthetic_minority_generation.ipynb` | High | High | High |

They are **complementary, not competing**: resampling changes exposure, uncertainty weighting changes the
loss balance, generation changes the data itself. In principle all three can stack.

## Recommended implementation order (and why)

**1st — Topic 2, Uncertainty-weighted loss.** Smallest, cheapest, lowest-risk change (four learnable scalars,
drops straight into the folder-3 loop, no extra data, no extra backward pass). Do it first because it removes
a *confound* that contaminates the other two comparisons: today's hand-picked `1:1:0.5:0.5` weights are an
unjustified guess, so any gain from resampling or synthetic data is entangled with "were the loss weights even
right?" A properly balanced multi-task baseline makes every later comparison clean — and it is a ~1-day win.

**2nd — Topic 1, Dynamic resampling.** Built on the balanced baseline, it targets the headline metric
(rare-class recall) most directly, is architecture-agnostic, and is only moderately more expensive. It also
*produces the resampling/oversampling control* that Topic 3 must beat to justify its cost.

**3rd — Topic 3, Synthetic generation.** Highest risk and compute, highest potential publishability, but it
only earns its keep if it beats good oversampling — so it needs Topic 1's resampling control to exist first as
the comparison. Do it last, as the ambitious swing.

## Publishability, in one line each
- **Topic 1:** publishable as a clean applied ablation (recall-driven curriculum sampler for medical imbalance).
- **Topic 2:** publishable as an applied clinical-MTL study; the method itself is established (be honest about that).
- **Topic 3:** genuinely publishable *if it works* — including as an honest negative result if synthetic fails to beat oversampling.

## Cross-cutting standards (applied in all three)
- **Evaluation:** grade → quadratic-weighted Cohen's Kappa (primary), balanced accuracy, MCC, confusion matrix;
  lesion → per-class & macro AUROC **and PR-AUC** (PR-AUC matters more under extreme imbalance), per-class recall.
  Headline = per-rare-class recall. Report **mean ± std over ≥3 seeds** with significance testing.
- **Split fix:** the repo's `train_test_split(random_state=42)` is **not stratified**; the new work mandates a
  stratified split on the rare-lesion indicator so rare positives don't land unevenly.
- **Kaggle reliability:** every notebook autodetects the dataset (glob), runs single-GPU **and** dual-T4
  (DataParallel + graceful fallback), uses AMP + gradient clipping, checkpoints every epoch + best-model to
  `/kaggle/working`, resumes from checkpoint, logs metrics to CSV, and fixes all seeds. Heavy training is gated
  behind a config flag so the notebook runs top-to-bottom unattended for grading/demo.
- **Known baseline bug to fix on the way:** `alternate_architechture.py` hardcodes CFP grade weights using
  UWF's grade-4 count (1553) instead of CFP's true 675 — recompute per modality if you touch grade weighting.
